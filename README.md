# 1C Publication Auditor

**Текущая публичная версия: v2.0.0**

Read-only веб-аудитор публикаций **1С:Предприятия**, опубликованных через Apache на Windows Server.

Auditor собирает в одной локальной веб-панели цепочку **Apache → публикация → каталог → .htaccess → default.vrd → база 1С**, показывает состояние каждой публикации и формирует рекомендации по найденным проблемам.

> Проект работает только на чтение. Он не изменяет `httpd.conf`, `.htaccess`, `default.vrd`, каталоги публикаций или базы 1С.

## Что проверяет

- публикации 1С и их `Alias` в `httpd.conf`;
- существование каталогов публикаций;
- наличие и содержимое `.htaccess`;
- ожидаемые ограничения `Require ip`;
- `AllowOverride` и правила `Require` в блоках Apache;
- наличие и разбор `default.vrd`;
- файловые и серверные информационные базы из VRD;
- наличие, размер и дату изменения `1Cv8.1CD` для файловых баз;
- дубликаты `Alias`, `Directory` и VRD `base`;
- случаи, когда одна база опубликована несколько раз;
- связи Apache → Directory → VRD → база 1С;
- каталоги в корнях публикаций, которые не найдены в конфигурации Apache;
- недоступные диски/сетевые пути и таймауты проверок.

## Интерфейс и отчёты

Проверка выполняется в отдельном PowerShell-процессе, поэтому локальная веб-панель остаётся доступной во время сканирования. В интерфейсе отображаются прогресс, итоговые статусы, причины проблем и рекомендации.

Результаты можно экспортировать в CSV для дальнейшей работы в Excel и в автономный HTML-отчёт.

## Требования

- Windows Server или Windows;
- Windows PowerShell 5.1;
- Apache HTTP Server с публикациями 1С;
- доступ учётной записи, запускающей Auditor, к `httpd.conf`, каталогам публикаций и проверяемым файловым базам.

Установка дополнительного веб-сервера, PHP, Node.js или базы данных для самого Auditor не требуется.

## Быстрый запуск

1. Скачайте исходники релиза и распакуйте их в отдельную папку.
2. Скопируйте `config.example.json` в `config.json`.
3. Отредактируйте `config.json`: укажите путь к Apache `httpd.conf`, корни публикаций и при необходимости ожидаемые правила `.htaccess`.
4. Запустите `Check-Syntax.bat`.
5. Убедитесь, что встроенные проверки завершились успешно.
6. Запустите `Start-Auditor.bat`.
7. Откройте `http://localhost:8787/`, если браузер не открылся автоматически.

Для остановки сервера закройте окно PowerShell/командной строки, в котором запущен Auditor.

## Конфигурация

Пример:

```json
{
  "ApacheConfigPath": "C:\\Apache24\\conf\\httpd.conf",
  "PublicationRoots": [
    "D:\\1c_web",
    "D:\\1c_web_local"
  ],
  "ListenPrefix": "http://localhost:8787/",
  "ExpectedHtaccessRules": [
    "Require ip 192.168",
    "Require ip 127.0.0.1"
  ],
  "HistoryLimit": 50
}
```

Рабочий `config.json` намеренно исключён из Git. Это позволяет хранить локальные пути и параметры конкретного сервера вне публичного репозитория.

Каталоги `data/` и `logs/` также являются runtime-данными и не должны попадать в Git.

## Как понимать статус внешнего доступа

`POTENTIAL_EXTERNAL` означает, что Auditor обнаружил конфигурацию Apache/`.htaccess`, которая не содержит ожидаемого ограничения доступа для существующего каталога публикации.

Это **не является доказательством доступности публикации из Интернета**. Фактический доступ также зависит от Windows Firewall, сетевого firewall, NAT, reverse proxy, VPN, маршрутизации и других уровней инфраструктуры.

Если каталог публикации отсутствует, это отдельная проблема конфигурации и она не должна интерпретироваться как внешний доступ.

## Безопасность

Auditor предназначен для административной диагностики собственной инфраструктуры. В публичный репозиторий не следует коммитить рабочий `config.json`, результаты сканирования, журналы, реальные VRD-файлы или иные сведения о внутренней инфраструктуре.

Правила сообщения об уязвимостях проекта описаны в `SECURITY.md`.
